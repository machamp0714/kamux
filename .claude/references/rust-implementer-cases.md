# 実例（rust-implementer）

`.claude/agents/rust-implementer.md` の規則を裏付けた実例。出典はすべて kamux（2026 年 8 月）。

規則の射程を判断するとき、または規則を消してよいか迷ったときに読む。普段は開かなくてよい。

## brief が正典ではない

2026-08-05 の実測で、brief 側の欠陥を 7 件踏んでいる。enum の末尾欠落 4 件、shutdown ゲートの位置、テスト指定の欠落、起動フェーズの構造。

うまくいったのは implementer が自分で契約を読んで直したケースである。M2-1 の implementer は、brief の型定義ブロックに `StateReason` が 12 個しか無いことに気づいた。契約 §8 と brief の Interfaces 節は「13」と明記していた。契約 585 行を逐語で確認して補完し、BLOCKED にせず進めた。

件数の比較が当てにならない実例もある。計画と契約で整形スタイルが違い、1 行へ詰めた宣言を過小に数えて、契約 §8 を 13 ではなく 7 と数えた。だから照合はメンバ名の集合で行う（契約 §68.3）。

brief のコード片が実物と食い違う形も出ている。M1-4 が `start_session` を分解したため、後続 brief の「クロージャで括る」という前提が消えていた。

## 報告に書いたテストが実ファイルに無かった

「テストを追加した」と報告したが、実ファイルには無かった事例がある。だから報告に書く前に `grep` で確認する。

## 同じ型の値を取り違える

契約 §72 / §81.2 の原型は Rust である。`impl StatePersist for Store` の `.map(|s| s.id)` を `.map(|s| s.project_id)` に取り違える変異が、`cargo test --workspace` 315 passed を丸ごと生き延びた。

対照的に `resize_pty(sid, cols, rows)` の `cols`/`rows` は同じ型が 2 本並ぶが、名前で判別できるので該当しない。

## 呼ぶ側の配線が無検査だった

台帳 #17。`resolve_cwd` の配線で、呼び出しを差し替える変異が全テスト緑を生き延びた。

台帳 #46。リファクタで観測点を切り出すと、切り出し元と切り出し先の継ぎ目が無検査のまま残る。

## 変異の復元が作業を丸ごと消した

2026-08-08、M2-3 Task 2 の作業が丸ごと消えた（台帳 #43 / #104）。レビュー指摘への追加修正をコミットせずに変異へ進んだ形である。

## difft と cwd が diff を壊す

このリポジトリは `diff.external=difft` なので、`git diff` は 2 カラムの表を描く。実測で 4 回起きており、うち 1 回は team-lead が「差分は無い」と誤判定した（台帳 #127 / #131 / #152 / #159）。

2 箇所同時に打ったとき、片方が無言で不適用でも「非空」は成立する（台帳 #138）。行番号指定の `perl` が直前の修正で行がずれて空振りした形は 4 ラウンド連続で起きた（台帳 #136）。修正が既存ブロックを複製して、一意だったアンカーが 2 箇所・6 箇所に増えた例もある（台帳 #141）。

台帳 #195 は別形。`cd src-tauri && … && git diff -- src-tauri/src/…` はパススペックが cwd 相対に解決されるため、変異が適用済みでも空を返す。`--no-ext-diff` を付けていても起きる。「変異した行を目で見る」という観測点は、出力自体が空なので射程外だった。

台帳 #151。単一行の `perl -pi -e` で表せない変異（複数行の挿入・削除）が「測れない」として落ちかけた。

## 変異が適用されているのに測れていなかった

台帳 #76。`match` にアームを足す変異をワイルドカード `_` より後ろに置いたため `unreachable pattern` になって発火しなかったが、`git diff --stat` は非空のままだった。

台帳 #90。`cargo build --workspace` は `#[cfg(test)]` を型検査しないので素通りし、テスト側の変異では `E0308` が出なかった。

## ハングと、無関係なフレーク

台帳 #57。`timeout` を挟まなかったため、実測で最も価値の高い 2 変異が「測定不能」として捨てられかけた。`timeout 120 cargo test --workspace; echo "exit=$?"` の `124` がその変異の赤である。

台帳 #41 / #71。無関係な実 PTY フレークが 1 本混入して「1 failed」になり、全緑の変異が赤と誤読されかけた。判別できたのは件数ではなく失敗テスト名を採取したからである。

台帳 #63。サンドボックス有効のままだと環境起因で 5 件落ちる。`pty/launch_env.rs` の `probe_*` 3 件は偽シェルの exec が阻害され、`hooks_srv/mod.rs` の `real_relay_*` 2 件は relay がソケットへ 10 秒以内に接続しない。

## プローブに判別力が無かった

stage4 で 6 回（台帳 #48 / #60）。

| 形 | 実例 |
|---|---|
| プローブが race をずらす | `eprintln` を挟んだ時点で再現しなくなる |
| プローブが遅すぎる | 子が既にゾンビで判別力が無い |
| 同じ構造のプローブを 2 本続けて作った | 観測スレッドが callsite の初回登録を先に取る |
| 対照が判別力ゼロ | 出力条件が正当に無音の否定テストまで拾い、最初の 120 回が全件ヒット |
| 対照が同一 | 否定テストのメッセージが quiet 側と loud 側で同じで、条件反転の変異が緑になった |

## 観測に判別力が無かった

- 台帳 #129。原理的に赤になり得ない変異（テスト配列から `CliKind::Shell` を落とす）
- 台帳 #130。`gate.rs` 規則 4 の変異が内側の網羅 `match` に masking され必ず緑
- 台帳 #91 / #161。2 変異が実装上まったく同じ 1 編集で、独立した 2 観測として報告された
- 台帳 #184。`WHERE` 句だけ削り `params!` を残したため `rusqlite` のパラメータ数エラーで落ち、意図した実行結果を見る前に赤になった
- 台帳 #193。hooks 疎通を測るはずの観測欄が、`BelDetected` / `SilenceTimeout` 由来の 🟡 / ⚪ に到達できた（`runtime_state.rs:149-150`）
- 台帳 #206。陽性の対照が純関数を直接呼ぶユニットテストで自明に赤くなる位置に在り、測りたかった `lib.rs:107` の配線を測らなかった

## パイプが終了コードを隠す

2026-08-15、team-lead がステージ完了ゲートでこの形を打ち、`cargo test` が 8 件しか見えなかった（実際は 783）。clippy が落ちていても緑と報告する形だった。

台帳 #40。`--no-fail-fast` を付けないと、先頭 target が赤になった時点で残り 3 target が黙って飛ぶ。

借りてきた指標が 2 状態を区別しない形も出ている。`git status --porcelain` は `.gitignore` 配下の成果物を見ない（台帳 #113）。`git ls-files -s` はインデックスのモードを返すので worktree の実行ビット喪失を見ない（台帳 #169）。ローカルの緑は CI の緑ではない（台帳 #115）。

## brief のコード片が実在しない型を前提にしていた

台帳 #148。brief のコード片が実在しない型 `SessionManager` を前提に書かれ、着手前に 6 件の読み替え打ち消しが必要になった（M2-4 Task 13）。同型は stage4 で 5 件出ている。`now_millis` / `self.conn.lock()` / `crate::store::tests::test_store()` ほか実在しない API 6 箇所、恒真になる罠を持つコード片、上書き型 API への「追加」指示。

## 処方が名指しした範囲ちょうどで閉じた

台帳 #155。処方が「指摘した 3 変異を赤にすること」だけで検証され、族の境界が誰にも書かれないまま逐語採用された。

台帳 #132。「1 語だけ」の訂正指示で `mod.rs:18` は直り `mod.rs:39` は残った。`grep -c '<誤記>'` = 2 が見えていれば起きない。

台帳 #69。3 項の論理積の第 1 項だけを閉じ、第 2 項が 6 本のレビューを無観測で通過した（`mod.rs:186-188`）。

## 参照の誤りが 5 箇所へ転記された

台帳 #149。advisor 指摘の §53.9.1 を本文照合せずに信用し、production 2 / test 2 / CSS 1 の計 5 箇所へ同じ誤引用を転記した。

台帳 #150。その手当てとして「旧文字列 0 件」を完了確認にした結果、5 箇所のうち 2 箇所が別の誤った参照へ置き換わった。rev1 の手当てが rev2 の穴を作っている。

## 測定の来歴が無く、事後に切り分けられなかった

台帳 #58。レビュー修正コミットの前で測った変異が「後に打った」と記載され、母数の 1 の差でしか検出できなかった。

台帳 #39。変異を戻した直後に再ビルドせず `target/debug/` のバイナリを直接起動し、実在しない 4 KiB のバグに見えた。

## 断定が変異を素通りする

旧版の規則は射程が報告だけだったため、`doc` コメント・テスト名・production のコメントへ書く断定が素通りした。PR #74 だけで 6 例出ており、うち 3 例は「前の穴を閉じるために書いた修正差分」が持ち込んだものである（台帳 #157 / #158 / #160 / #168）。修正ラウンドが断定を増やす形は 3 連続で起きた。

| 例 | 断定 | 実測 |
|---|---|---|
| テスト名 `… and never polls` + `HooksStatusPanel` の doc「定期リフレッシュはしない」 | ポーリングしない | `setInterval(…, 1000)` を注入して 669 全緑 |
| `bel.rs:213` の doc「定数 → スクリプト本文の対応表」 | 対応が検査されている | 対応そのものを測る assert が無く、3 変異が全緑 |
| `bel.rs:338` の doc「`DONE` の後の待ちは」 | 位置が固定されている | `sleep` を `DONE` の前へ移す変異が 161 passed で全緑 |

実測されていない「設計上の不可能性」も断定である（台帳 #47 / #133 / #167）。双方向に 4 回、相手が試作で反例を作っている。

## dispatch と定義ファイルの優先順位が書かれていなかった

stage5 で 4 回（台帳 #135 / #139 / #153 / #163）。うち 2 回は「変異は 1 回に 1 箇所」に対して dispatch が 2 箇所同時を要求した形である。PR #74 では 10 本のレビューのうち 1 本だけが別の解釈を採り、その 1 本だけ欄が空になった。

## 規則を書いた本人が同じ便でその規則を破る

stage5 で 5 回（台帳 #124 / #125 / #128 / #142 / #144）。実装ロール側の形は #144 で、「測っていない主張をコメントに書いた」という指摘への修正の中で、その修正自身が測っていない主張を新しく書いた。

台帳 #196 / #201。群 U は 5 つの定義ファイル全部に在るのに、2026-08-14 に両側で同日再発した。#196 は実装者が自分の報告 `:144` に記録した罠を次の便で踏んだ形で、その行自身が逐語で「警告文では閉じない。手当てはコマンドの形でなければならない」と書いている。

## マーカの後に作業を続けた

stage4 で 4 回。`STATUS: …` の行を書いたあとに作業を続けて実害が出た。レビュアーへ古い差分を渡した。同じ worktree で implementer が 2 体並列に走った。PR 本文の数値が 1 コミット前になった。dispatch に禁止を逐語で書いたうえで起きているので、規律ではなく順序の問題である。

## 報告ファイルに版が残らない

台帳 #56 / #67。報告ファイルは git 管理外なので、記述が偽になった時点を事後に切り分けられない。#56 は未実行の `git diff` を「実行済み」と書いた形である。
