# 実例（lane-controller）

出典はすべて kamux（2026 年 8 月）。`lane-controller.md` と層2 ファイル（records / completion / handoff）の規則を裏付けた実例・実測・経緯をここへ退避してある。
規則の射程を判断するとき、または規則を消してよいか迷ったときに読む。普段は開かなくてよい。台帳番号（`#N`）は `.claude/AGENT-LESSONS.md` の「## 事象」の行を指す。

## brief のコード片が持ち込んだ欠陥は 5 つの形を取った

stage4 で 5 件出た。

| 形 | 実例 |
|---|---|
| 計画のコード片が欠陥を持ったまま逐語で実装された | `accept` ループの `Err` 枝が無待機スピンで CPU を 1 コア占有（契約 §0 のアイドル CPU は硬い制約。`set_nonblocking` / `sleep` の grep では検出できない）/ `matches!` だけの assert が失敗の理由を区別しない |
| 実在しない API を呼んでいる | `now_millis` / `self.conn.lock()` / `crate::store::tests::test_store()` ほか 6 箇所。そのまま渡せばコンパイルエラー |
| 恒真になる罠を持つコード片 | `wait_state(tx, id, want)` は `want` が `RuntimeState` の既定値（マップ未登録時に `current()` が返す `Idle`）のとき問答無用で恒真になる。brief のコード片自身がその形だった |
| 例示した担保手段が担保しない | 「`match` の網羅ガード」を網羅担保の例として示したが、`match` の網羅エラーは配列リテラルの更新を強制しない。フィクスチャを 1 種落としても 530 全緑のまま `every` を名乗るテストが残った |
| 上書き型 API に「追加」を指示した | `tauri::Builder::setup` は `self` を取ってフィールドを上書きする。2 つ目を足すと 1 つ目が黙って消え、`AppState` が一切登録されなくなる。`cargo test` は `run()` を通らないので捕まえない |

`main.rs` → `lib.rs` の読み替えが brief 側にだけ残っていた例がある（brief を先回りして切った形）。

2026-08-15 に 6 回目として書き直された。#148 は brief のコード片が実在しない型 `SessionManager` を前提に書かれ、着手前に 6 件の読み替え打ち消しが必要になった（M2-4 Task 13）。

## 検証 E は 3 版連続で壊れていた

1 版目 `git rev-list --count --merges "$MC" -1` は決して 0 を返さない（PR #63 のマージで実測して発覚）。`git rev-list --merges <commit>` は `<commit>` 自身がマージかを見るのではなく、そこから履歴全体を遡ってマージコミットを探す。
本リポジトリは PR #1 が真のマージコミット（`0bed3b7`、親 2 つ）で入っており、それが全ブランチの祖先にあるため、`--max-count=1` が付いていても必ず 1 が返る。
検算: 既知の正常な squash マージ 2 件（`993dafe` = PR #59 / `3cc3225` = PR #63）に当てて両方 `1`。合格と不合格が同じ出力になる形であり、契約 §99.2 / §101.7 の族である。

2 版目 `git cat-file -p "$MC" | grep -c '^parent '` も誤りだった。次のマージ（PR #61、`689d21e`）で偽の警報を出した。
`cat-file` はコミットオブジェクト全体を吐くので、squash されたコミットメッセージ本文に `parent ` で始まる行があると数に入る（実物: `689d21e` の 322 行目 `parent attach useLayoutEffect sees isStarted=false …`。
テスト名である）。squash（罠あり）= 2 / 真のマージ = 2 で、ここでも合格と不合格が同じ値になる。

現行の `git show -s --format=%P "$MC" | wc -w` は親ハッシュだけを出すのでメッセージ本文の影響を受けない。検算 3 件: `689d21e`（squash・本文に罠あり）= 1 / `5d87fae`（squash）= 1 / `0bed3b7`（真のマージ）= 2。

3 版目 `[ "$(… | wc -w)" = "1" ]` も macOS で壊れていた。BSD の `wc` は数値を右詰めするので出力は `"       1"` であり、文字列比較 `= "1"` は必ず偽になる。1・2 版は「合格と不合格が同じ値」だったが、これは「合格が必ず不合格を返す」形である。
