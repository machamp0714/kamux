# lane-controller: 引き継ぎ（詳細）

`lane-controller.md` の層2 ファイルである。引き継ぎで降りるとき、または引き継ぎを受けて起動したときに読む。読んだら ledger へ `参照: lane-controller-handoff.md（<局面>）` の 1 行を記帳する。引き継ぎの判定条件（2 タスク・PR マージ・未コミットで降りない・`TIP` 保持）は本体が持つ。

## 切れる場所

| 局面 | 動き | 作業ツリー |
|---|---|---|
| PR のマージ直後 / スタック直後 | 本体の規則どおり引き継ぐ | clean |
| 人間ゲート待ち | BLOCKED を返して終了するので、同じ応答で引き継ぎ報告も返す | clean |
| 契約変更要求の裁定待ち | 裁定は `progress.md`「## 裁定」に残るので引き継げる | clean |
| セッション上限が近い | 引き継ぐ | clean でなくてよい（本体の例外） |

このうち 3 つはタスクの途中で起きる（その時点で当該タスクの完了行は未記入だった実測がある）。判定をタスク境界ではなく作業ツリーの状態で書いているのはこのためである。

## 引き継ぎ報告の本文

`SendMessage` で送る規則と ledger への `Handoff:` 行は本体が持つ。本文には次を入れる。

```
引き継ぎ / フェーズ: M?-?  PR: #<n>
ブランチ / HEAD: <branch> / <sha7>
完了したタスク: Task <N> まで（ledger の該当行は記入済み）
次に着手するタスク: Task <N+1>
マージ許可: あり / なし          ← 規約からは復元できない。必ず書く
人間ゲート待ち: （あれば内容。無ければ「なし」）
park / 契約変更要求: （未解決があれば。無ければ「なし」）
未コミット: なし / あり（あるならセッション上限の例外。git status --short を添える）
ledger に書ききれていない判断: （あれば 1 行。無ければ「なし」）
```

差分やコード全文を貼らない。次のレーンは ledger と `git log` から復元する。

## 引き継ぎを受けた側が最初にやること

本体の ledger 節【規則 2】を実行する。「ledger の最終完了行」と「ブランチの最終コミット」が対応しているかを確かめる。この行が、あなたが 2 タスクを数える起点になる。

不一致でレビュー記録を復元した場合は、復元後の最終完了行を起点に取り直す。復旧で完了行が 1 本増えるので、取り直さないと起点が古いまま 3 タスク走ることになる。

ただし完了行が `no commit` のタスクでは、この検査は一致も不一致も返さない。検証タスクなど「実装差分ゼロが正」のものがこれに当たる。その場合は evidence ファイルの存在で代える。
所在は ledger の当該完了行が持っている（`Task 17: complete (no commit — 人間ゲート実施 …)` の形で、evidence の場所がそこに書かれている）。`docs/superpowers` と `.superpowers` は `.git/info/exclude` により worktree に存在しないので、絶対パスで参照する。
