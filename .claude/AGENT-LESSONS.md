# エージェント定義の学び（AGENT-LESSONS）

**このファイルは「事象」を溜める場所であって、規則を書く場所ではない。** 規則の形にするのは昇格時である。

設計は `docs/superpowers/specs/2026-08-05-agent-self-improvement-design.md`（**git 管理外**。設計書は git で管理しない方針なので、clone しただけの環境には無い）。

## 正典の分界

> **作るものの話（仕様・型・命名・順序・値）は契約** `docs/superpowers/plans/2026-08-01-kamux/00-contracts.md`。
> **作り方の話（誰がいつ何を確認するか）が本ファイルと `.claude/agents/*.md` / `.claude/skills/kamux-lane/SKILL.md`。**

**契約に書けば防げたものを本ファイルに書かない。** それは契約変更要求であり、contract-owner の専管である。

## 書き方

| 規則 | 内容 |
|---|---|
| **事象で書く** | 「◯◯すべき」ではなく「◯◯が起きた」。規則の形で溜めると微妙に違う規則が並び、**2 件目が同じ穴かどうかを判定できなくなる** |
| **1 行に収める** | **表のセルは改行を含められない。** 改行した瞬間に表が壊れる |
| **0 件なら何も書かない** | 「特になし」の行を残さない。**0 件は正常な結果である。** 残すとファイルが「なし」で埋まり、実在の事象が埋もれる |
| **棄却も行として残す** | 一度考えて捨てた判断を消すと、**同じ議論が再燃する**（契約が全章に却下記録を持つのと同じ理由） |

| 源 | 誰が書くか | いつ |

| PR レビューの `定義の穴:` 欄 | lane-controller | **`gh pr merge` の前**に、その PR のブランチへ転記する |
| **ユーザーからの指摘** | team-lead | 指摘を受けたその場で |

## 昇格

**判定の手順・閾値・昇格 PR の要件は `.claude/skills/kamux-lane/SKILL.md` の「ステージ完了ゲート」が持つ。本ファイルには書き写さない** —— 書き写した瞬間に二重の正典になり、片方だけ直せば静かに乖離する。

**本ファイルが持つのは `昇格` 列の語彙だけである。**

| 値 | 意味 |
|---|---|
| `—` | 未昇格。ゲートが数える対象 |
| `昇格済み（<short sha>）` | 定義ファイルへ反映済み。sha は昇格 PR のマージコミット |
| `棄却（<理由>）` | 昇格しないと判断した。**行は消さない** |

**規則が増え続けると読まれなくなる。ただし「一定期間発火しなかったから消す」という自動の引き金は置かない** —— **規則が発火したことを観測する主体が、この鎖のどこにも居ないからである。** 観測されない指標を列に持つと、全ての規則が「発火なし」に見えて削除候補に落ち続ける。

> **棚卸しは、定義ファイルが読みにくくなったと感じたときに手で行う。**
> **消す前に、その規則を外したら何が起きるかを 1 行書く。書けないなら残す。**

**発火しないのは、予防できているからかもしれない。** 守っているものを壊してみて初めて守っていたかが分かる —— 変異検証と同じ思想を規則自身に適用する。
