# エージェント定義の学び（AGENT-LESSONS）

**このファイルは「事象」を溜める場所であって、規則を書く場所ではない。** 規則の形にするのは昇格時（下記）。

設計は `docs/superpowers/specs/2026-08-05-agent-self-improvement-design.md`（git 管理外）。

## 正典の分界

> **作るものの話（仕様・型・命名・順序・値）は契約** `docs/superpowers/plans/2026-08-01-kamux/00-contracts.md`。
> **作り方の話（誰がいつ何を確認するか）が本ファイルと `.claude/agents/*.md` / `.claude/skills/kamux-lane/SKILL.md`。**

**契約に書けば防げたものを本ファイルに書かない。** それは契約変更要求であり、contract-owner の専管である。

## 書き方

| 規則 | 内容 |
|---|---|
| **事象で書く** | 「◯◯すべき」ではなく「◯◯が起きた」。規則の形で溜めると微妙に違う規則が並び、**2 件目が同じ穴かどうかを判定できなくなる** |
| **0 件なら何も書かない** | 「特になし」の行を残さない。**0 件は正常な結果である。** 残すとファイルが「なし」で埋まり、実在の事象が埋もれる |
| **棄却も行として残す** | 一度考えて捨てた判断を消すと、**同じ議論が再燃する**（契約が全章に却下記録を持つのと同じ理由） |

## 昇格（判定はフェーズ完了ゲート。手順は `.claude/skills/kamux-lane/SKILL.md` §6）

| 状況 | 動き |
|---|---|
| **同じ穴が 2 回以上** | **定義ファイルへ昇格させる PR を作る。** 1 回は偶然、2 回は構造 |
| 1 回だけ | そのまま残す（消さない） |
| **3 フェーズ跨いで 1 回のまま** | **棄却**として記録し、行を閉じる |

**昇格 PR には 2 つを必ず書く。**

- **なぜ**（実例と日付）—— **理由の無い規則は次のレーンが消す**（契約 §68.8 の実測）
- **観測点**（効いたと分かる signal）—— 無いと効いたかを測れない。**issue #51 の受け入れ条件 5 がその形だった**

**昇格 PR は通常の PR レビューを通す。** PR #52 では `task-reviewer.md` の追記が既存記述（「読み取り専用」）と矛盾しかけ、レビューで検出された。**定義の変更こそ差分レビューが要る。**
