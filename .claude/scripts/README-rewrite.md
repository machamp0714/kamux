# 定義ファイルの書き直し（issue #94）の道具と手順

`.claude/` の定義ファイルを `kamux-promotion/SKILL.md` と同じ書き方へ揃える作業で使う。
**規則の内容は変えない。書き方だけを変える。落ちた規則が 1 つでもあれば不合格。**

対象と順序: `contract-owner.md`（済） → `web-implementer.md`（済） → `rust-implementer.md` → `task-reviewer.md` → `kamux-lane/SKILL.md`

## 道具

| | 何を測るか |
|---|---|
| `check-rewrite.py` | 受け入れ条件（🔴 / 日付 / 台帳 # / 200 文字 / § / 太字 / 見出しの参照 / code fence / 守る逐語） |
| `check-survival.py` | 旧版の文が新版か退避先に痕跡を残しているか |

```bash
python3 .claude/scripts/check-rewrite.py . <定義ファイル> <退避先> \
  --chapters=<件数>:<ダイジェスト> [--renamed=<件数>:<ダイジェスト>] \
  [--anchor=<逐語> ...] [--no-anchors] [--no-fence] [--no-chapters] [--no-decorated]

python3 .claude/scripts/check-survival.py . <定義ファイル> <退避先> [--base=<ref>] [--new=<ref>]
```

誤った引数は FATAL になり、`--chapters` は正しいコマンド全体を印字する。**散文に書いた再現コマンドは器が変わるたびに古くなるので、器の出力を貼ること。**

## 🔴 「全合格」は欠落 0 件の根拠にならない

`check-rewrite.py` は見出しと code fence と手書きアンカーしか見ない。**見出しと見出しの間の散文が 1 本消えても全検査が緑になる。**
欠落の唯一の根拠は人手の突き合わせ台帳である。

## 母数の検算は 4 本立て

それぞれ出ないものが違う。1 本では足りない。

| 検査 | 出ないもの |
|---|---|
| ラベル列の機械導出 | 内容の欠落（形式しか見ない） |
| 補集合（台帳が指さない行の機械列挙） | 引かれた行の中の、分解されなかった節 |
| 弁別トークン（識別子・API 名・ファイル名・`\d+ ?(件|本|回|箇所|行)`） | 具体値を持たない散文 |
| 文単位の生存検査（`check-survival.py`） | 意味が変わった書き換え |

**PR #95 / #96 で出た規範項目の欠落 3 件は、すべて「台帳の粒度が行」に由来する。** 行を引いていれば行の中の節が落ちても補集合に出ない。

**ラベル列を機械導出するときは code span を退避させてから分割する。** 素の `split('|')` では割れる。行数は正しい数を返すので、行数検算だけでは気づけない。

## 判定の物差し —— これが検査の本数より重要

> **読者の行動を変える文か。** 変えるなら規範項目（規則本体でも、理由でも、帰結でも、観測点でも）。変えないなら経緯・メタ。

- **候補文が乗っている行の台帳項目が `削除` / `退避` でも、その分類を文へ継承しない**
- **判定して外した候補は、件数と理由を書く。** PR #96 の欠落 3 件目は、検査は候補として出していたのに「確信度が低い」として外され、外したことが記録されなかったため誰にも見えなかった
- **🔴 文末の様相（命令形・義務表現）で絞ってはいけない。** PR #95 / #96 で落ちた 3 件はいずれも帰結・理由を述べる文だった。**欠落は規則本体ではなく、いつも理由・帰結の側で起きている**

## 書き方の型

- 見出しから `🔴`・群ラベル・日付・太字を外す。**見出しのコアが変わったら `--renamed=` で宣言する**（意図的な改名はありうるが、件数だけでは「1 本直して 1 本消す」が素通りする）
- 実測・台帳の行番号・章番号の羅列は `.claude/references/<名前>-cases.md` へ退避し、本文からは末尾 1 行で指す
- 退避先は `.claude/agents/` の**外**に置く（`.claude/agents/**` が走査対象になりうる）
- 🔴 は 1 ファイル 3 個まで（実績は 2 個）
- **`§` の分界は用途で決まる。組版ではない。** 章を値として書き込むなら `§25`、場所として名指すだけなら「25 章」。書き込む先は production のコメント・テスト名・コミットメッセージ・レポートファイル・`SendMessage` の本文・BLOCKED の理由・契約変更要求
- frontmatter（`name:` / `model:` / `tools:` / `description`）も母数に入れる。`color:` は装飾なので明示的に除外すると宣言する

## レビュー

2 体を独立に立てる。**変異は指定しない**（全件レビュアーが設計する）。**実装を揃えない** —— 同じ道具を 2 者で使えば一致は独立の裏付けにならない。

依頼に必ず入れるもの:

- 対象 tip の完全な sha。**`git rev-parse HEAD` の出力をそのまま貼り、`git cat-file -t` で解決も確認する。** `--short` の出力から残りを作らない
- 突き合わせ台帳のパスと母数の宣言
- **退避項目を弁別トークンで全件照合してほしい**
- 変異は隔離ツリーで打つ（`git worktree add --detach`）。共有ツリーに入らない
- 観測を引用するときは測定時の sha を添える
- 判定は `SendMessage` で返す（地の文は届かない）

**判定が返るまで作業ツリーも器も触らない。** PR #95 では 12 回動かしてラウンドが 6 に伸びた。

**承認は blob で固定する**（`git rev-parse <sha>:<path>`）。tip が動いても、承認の対象が何だったかは blob で一意に決まる。

## 🔴 修正ラウンドは、穴を減らしながら同時に増やす

3 本目は 6 便で 6 件出した。**指摘を閉じる便が別の穴を開けた形が 6 件中 6 件である。** 機構が 2 つあり、手当てが違う。

| 機構 | 実例 | 手当て |
|---|---|---|
| **人が判断を誤った** | 契約の射程を狭めて書いた（正典の主語は「テストコード内の値」なのに章題の「フィクスチャのガード」を主語にした）/ 旧版が言っていない優先順位を加筆した / 免除を輸入して**その理由の帰結を落とした** | 物差しを書く。**足した文を新規記述として一次資料に当てる** |
| **台帳の説明表が本表と同じ行頭を持つ** | 説明用の表を `\| 398 \|` の形で書くと、ラベル列の導出正規表現 `^\\\| \\d+ \\\|` に当たって**本表の件数と重複通番を汚す。3 本目・4 本目で計 3 回踏んだ** | 説明表の番号は `#398` の形で書く。**導出を打てば重複通番として必ず出る** |
| **判断は正しく、編集操作が裏切った** | 置換を `s[:i] + block + s[j:]` で書き、`j` が `i` より前に在ったため `s[j:i]` が丸ごと複製された。**置き換えたつもりが追記になっていた** | **編集後に構造を機械で見る** —— 見出しの重複を数える / 旧版との非空行の集合差を取って全件裁く |

**4 本目・5 本目は 484 行と 584 行で、置換スクリプトを使う場面が必ず来る。** 後者の手当てを最初から入れること。

**欠落は規則本体ではなく、いつも理由・帰結の側で起きる。** 3 本目で出た欠落 3 件も、復元が落とした 2 件も、全部そちら側だった。

## 🔴 変異が当たっていないと「検査の穴」に見える

4 本目のレビューで、**規範項目の欠落を数える側のレビュアーが偽の緑を 2 件出しかけた。** `perl -CSD -pi -e 's/…/…/'` が**マルチバイトのパターンに対して無音で不発した**ためで、
2 件とも exit=0（全緑）を返し、「検査がゲートしていない」と読みかけた。**置換が当たっていなかっただけである。**

台帳 #195（`cd` でパススペックが外れる）/ #136（行番号指定で行がずれる）と同じ族だが、
**原因が「置換ツールがマルチバイトで黙って何もしない」形で、既存のどの行もこれを名指ししていない。**

**手当て: 変異は python の `str.replace` ＋ `assert s.count(a)==1` で打ち、`git diff --no-ext-diff` の目視を必ず挟む。**
`task-reviewer.md` の手順ブロックが既にその形を持っている（複数行変異の python ブロック）。

**zsh には `PIPESTATUS` が無い。** `cmd | grep …; echo "exit=${PIPESTATUS[0]}"` は空を返す。
検証は単独で走らせて `$?` を読む。4 本目で 1 回踏んだ。

## 検査を新設したら、既存の検査との分業を実測で書く

4 本目で検査 11 に順序依存ダイジェストと 11b を足したとき、**「M4 は M1 と同じ機構だから同時に閉じている」と測らずに書いて偽だった。**
実測すると **11b と順序依存ダイジェストは素な分業**で、片方を外すと片方の族が静かに開く。

**放置すると「片方は冗長」と読んで外される。** 新設した検査には、**片方ずつ無効化して緑になる形**をコメントへ残すこと。

## 5 本目（`kamux-lane/SKILL.md`）で先に効くこと

**このファイルは `> ` 付き fence を 8 本（4 ブロック）持っている。** 素の fence は 12 本。
**検査 11 のガードは必ず FATAL を出す** —— 誤検出ではなく、4 本目で直したのと同じ形（`> ` 付き fence は
`code_lines()` が fence と数えないので中身が逐語保護の外へ出る）である。**素の fence へ移し、増えた行を `--fence=` で宣言する。**
他の 4 本（`lane-controller` / `contract-owner` / `web-implementer` / `rust-implementer`）は 0 本。

**ガードの偽陽性が 2 形ある**（4 本目の時点でどちらも母数 0 だったので閉じていない）。

| 形 | いま |
|---|---|
| 箇条書きの中に字下げした fence（正当な markdown） | FATAL になる。字下げを外すと箇条書きの入れ子が崩れる |
| fence の中に字下げした ``` の見本を書く | FATAL になる。その行は fence の中身で検査 11 が既に守っている。ガードが fence の内外を見ていない |

後者は `code_lines()` と同じトグルを回して fence の中の行を除けば安い。**`> > ` （`>` の間に空白がある入れ子引用）も今は抜ける。**

## 台帳番号の照合は境界込みで書く

**素朴な `'#' + n in text` は短い番号が長い番号に食われる。** `#1` が `#116` に当たる。

**4 本目で 2 体が別々の箇所で踏んだ** —— 実装側は判定で（12 件と出て 13 が正しかった）、レビュアー側は
表示用ロケータで（`#1` の出所を `#195` の行として印字した）。**同じ照合作業の中で 2 回出ているので、書く前に閉じること。**

```python
present = set(re.findall(r'#(\d+)', text))   # 抽出してから集合で当てる
```
