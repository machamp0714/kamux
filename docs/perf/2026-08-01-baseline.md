## 計測条件の数え方（契約 §104 の正典。別の数え方をしないこと）

- メモリは **4 プロセスの RSS の総和**（kamux 本体 + `com.apple.WebKit.WebContent` + `com.apple.WebKit.GPU` + `com.apple.WebKit.Networking`）である（契約 §104.2）。
- **PTY 子孫**（`claude` / `nvim` / シェルとその子孫）は上の総和に**含めない**。ただし子孫を含めた合計値も**参考値として必ず併記する**（契約 §104.2）。
- 対応づけは**起動時刻**で行う。**`ppid` では辿れない**（WebKit ヘルパは `ppid = 1` が既定である）（契約 §104.2 / 実測 3）。
- アイドル CPU は **60 秒平均 < 1.0% かつ最大サンプル < 5.0%**。測り方は `top -l 61 -s 1`、**1 ブロック目を捨てて 2〜61 ブロック目を使う**（契約 §104.3）。

**S-19 の前提確認（実施者が最初に 1 回だけ行うこと。コマンドと期待は第1部 §1.5:259-262 の逐語）**:

`is_scratch` 列は schema_version 3 で入る。**本ブランチのアプリを 1 回起動して移行を走らせてから**でないと、S-19 の件数クエリは `Error: in prepare, no such column: is_scratch` を返す（起動前の `SELECT MAX(version) FROM schema_version;` は 2 だった）。起動してから次の 2 つを打ち、両方が真であることを確かめてから S-19 に入ること —— これがこの観測の陽性の対照である。

```bash
sqlite3 "$HOME/Library/Application Support/kamux/app.db" "SELECT MAX(version) FROM schema_version;"
# 期待: 3
sqlite3 "$HOME/Library/Application Support/kamux/app.db" "PRAGMA table_info(sessions);" | grep is_scratch
# 期待: 1 行返る（空なら移行が走っていない。この状態で件数 0 を「増えていない」と読まないこと —— エラーと 0 は別である）
```
